# Contributing

Start with [the contributor guide](docs/contributing.md). Use the bug or proposal
form; a small fix can use the pull request alone. Include affected versions,
reproduction or motivation, compatibility and English/Russian impact, and license
acknowledgement. Do not put secrets in issues or examples.

A maintainer records a reason, responsible role and next action. Automation reports
missing information and check results. It cannot accept a proposal, approve a PR,
close an issue, merge a change or grant release authority.

Normative and authority changes require an owner decision before implementation.
Every merge needs current independent approval and successful current checks.
New commits dismiss stale approval. See [governance](GOVERNANCE.md) and
[security reporting](SECURITY.md).
