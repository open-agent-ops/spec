# Глоссарий Agent-Ops
## Управляемый словарь v0.4.0

**Исходная ревизия aom-03-r12 | приоритет английской версии**

> Буквальные идентификаторы и значения схем не меняются между языками; пояснения могут быть локализованы.

## 1. Основные термины

| Термин | Управляемое значение |
| --- | --- |
| Agent-Ops | Методология эксплуатации, объединяющая детерминированные доказательства, ИИ-анализ и изменения, пропускаемые через контрольные ворота. |
| Operational Intent | Версионируемые цель, область, ограничения, критерии успеха и идентичность автора; это не команда на исполнение. |
| authority | Явное полномочие субъекта на действие в заданных области и времени. |
| capability | Техническая возможность, сама по себе не дающая полномочия. |
| exact target | Неизменяемая идентичность содержания, оцениваемая доказательством. |
| evidence | Проверяемый, связанный с точной целью факт или ссылка на источник с идентичностью производителя и результата. |
| Evidence Bundle | Неизменяемый пакет идентичности, доказательств, решений и ссылок на исход. |
| admitted identifier (допущенный идентификатор) | Идентификатор цели, ресурса или объекта, выданный либо авторитетно подтверждённый системой без модели, допущенный детерминированным механизмом разрешения в актуальный Evidence Bundle (пакет доказательств), связанный с точной целью, и свежий на момент использования. |
| oracle | Объявленное правило оценки обязательства. |
| unit of work | Ограниченное изменение с проектом, реализацией, проверкой и закрытием. |
| Harness | Версионируемый проектный пакет Operations-as-Code. |
| Governance Mesh | Сквозной слой политик, проверяющий переходы процесса. |
| Autonomy R0-R5 | Риск-адаптивная лестница разрешений от режима только чтения до автономии в изолированной песочнице. |
| Capability C0-C5 | Лестница возможностей Agent-Ops: Observe, Explain, Plan, Prepare, Apply и Self-Heal. |
| Impact I0-I5 | Отдельная шкала эксплуатационного воздействия и требуемого контроля. |
| Guardian | Независимый проверяющий без полномочий на исполнение. |
| Outcome (результат) | Запись, создаваемая на этапе Verification (проверки) из доказательств состояния точной цели после изменения; она указывает, выполнены ли критерии успеха Intent (намерения) со статусом `succeeded`, `failed` или `unknown`, а этап Learning (извлечения уроков) использует эту запись. |
| RCA | Основанное на доказательствах ранжирование проверяемых гипотез, а не безусловное утверждение. |
| Remediation Planner | Компонент, готовящий предложение изменения без его применения. |
| Gated Executor | Отдельный исполнитель утверждённых действий с ограниченными учётными данными. |
| Decision Log | Добавляемая без перезаписи запись решений, утверждений, сроков действия, ссылок на доказательства и исходов. |
| Process Trace (трасса процесса) | Добавляемая без перезаписи упорядоченная запись каждого входа в шаг жизненного цикла и выхода из него, попытки перехода, решения и существенной реплики инженера или агента, связанная с субъектом, полномочием, доказательствами, результатом и точной целью. |
| Agent skill | Пакет `SKILL.md` с сопровождающими ресурсами, который агент обнаруживает, загружает в контекст и исполняет со своими полномочиями. |
| Skill manifest | Заявленные идентичность, разрешения, зависимости и класс риска навыка. |
| Risk tier | Заявленный класс риска; утверждение автора, подлежащее независимой проверке. |
| Agent artifact inventory | Перечень навыков, инструментов и MCP-серверов, разрешённых к загрузке. |
| Backbone model | Модель, фактически исполняющая артефакт в данном узле. |
| Injection resistance | Устойчивость к исполнению инструкций, пришедших как данные; свойство исполняющей модели, а не артефакта. |
| Admission receipt | Подписанная запись решения, созданная до потенциально опасного шага. |
| Outcome receipt | Подписанная запись результата исполнения, связанная со своей admission receipt. |
| Coverage record | Запись о том, что проверялось, что пропущено и где проверка была прервана. |
| Manifest stripping | Потеря заявленных ограничений при переносе артефакта между средами исполнения. |
| mutation conflict domain (домен конфликтующих изменений) | Определённое политикой множество пересекающихся областей изменения цели, попытки в котором взаимно сериализуются до Verification (проверки) или окончательного освобождения резервирования. |
| constructed-state evaluation (оценка на сконструированном состоянии) | Оценка, начинающаяся с точного проверенного предшествующего состояния, добавляющая один стимул и проверяющая получившиеся артефакты и решение; она не доказывает переходы, создавшие предшествующее состояние. |

## 2. Термины результата

`ok` означает, что все блокирующие входы известны и удовлетворены. `unknown`, `partial`, `stale`, `mismatched`, `conflicting`, `unauthorized`, `unreviewed`, `blocked` и `error` — разные неуспешные результаты. Ни один из них НЕ ДОЛЖЕН сводиться к успеху.

## 3. Термины публикации

`agent-ops.ru` — публичная идентичность методологии. `open-agent-ops` — имя репозитория. `source_revision` связывает двуязычные документы с одним состоянием английского источника.

## 4. Термины ролей

Реализатор создаёт ограниченное изменение. Проверяющий оценивает точную цель. Двуязычный рецензент оценивает смысловую эквивалентность. Ответственный владелец принимает решение о закрытии. Один человек МОЖЕТ совмещать несколько ролей только там, где это разрешает применимое правило разделения.

## 5. Правило перевода

Каждый перевод ДОЛЖЕН сохранять буквальные идентификаторы, значения перечислений, имена схем, свёртки и нормативную силу. Русский обычный текст ДОЛЖЕН сопровождать каждое употребление английского термина русским пояснением в скобках, а не только первое употребление. Буквальные значения в обратных кавычках, зарегистрированные названия продуктов, названия источников и общеупотребительные сокращения освобождаются от этого правила только тогда, когда перевод исказил бы идентичность; окружающий текст всё равно объясняет их роль. При конфликте английского и русского смысла действует английский, пока утверждённый преемник не изменит оба документа.
